# 给 AI 的 Mod 开发标准

这份只给正在帮作者写钢铁指挥官 Mod 的 AI。玩家说明在仓库 README。不要为了答一句去读管理器的 `MainViewModel.cs`。

核对日期：2026-10-08。数字以当天仓库为准，过期了就改数字，不要沿用记忆。

不要向作者追问用哪条路把 Mod 交出去。下面的规则与交件方式无关。

## 你是谁

你只生成客户端体验向的 Mod。你不改管理器，不在游戏运行时改写别人已经编译好的 DLL，也不承诺「装了这个就不会封号」。

Data Error 的公开后果是：这一局判负，并且不能重连。它不是已经核实的永久封禁。游戏自己的缺陷和丢包也会写出同一条记录。

## 现在的版本

- 管理器：`1.3.17`。
- 社区目录 `catalog.json` 的 `updatedAt`：`2026-10-08T09:15:00Z`。
- 目录里现有条目的 `minManagerVersion` 是 `1.3.14`。简介里若写着「需要 1.3.13」，那是旧句子。管理器只认 `minManagerVersion` 字段，不认简介。
- 新 Mod 若用现行的 `parts` 下载，`minManagerVersion` 不得低于 `1.3.14`。不要写成 `1.3.17`，除非这个 Mod 确实依赖只有 1.3.17 才有的行为。
- 字段格式必须是不带前导零的 `major.minor.patch`，例如 `1.3.14`。不要写 `v1.3.14`。
- 安装器附带的 MelonLoader 是 `0.7.3`。作者按这个加载器来写 MelonMod。

## 先问完再写

缺了下面任何一项，就停下来问作者。不得用占位符，也不得从文件名猜作者名、版本或支持哪一端。

哈希和体积不要问作者。那两项由 `python scripts/stamp_hashes.py` 填写。

- **身份。** 玩家看见的作者名，写入 `author`。联系方式不写进简介。
- **标识。** 提议一个 `id`：小写字母、数字、连字符，并与文件夹名相同。请作者确认目录里还没有这个 `id`。
- **名称。** 中文显示名，写入 `name`。
- **简介。** `summary` 只写三件事：玩家能做什么、用哪个键、正式服 / 测试服 / 两者。目录没有单独的游戏端字段，端写在简介里。不要写管理器版本号。不超过 400 字。
- **译文。** 按现有目录，再起草英文、德文、日文、俄文的 `locales` 名称和简介。给作者看过再定稿，不要自己当成已经确认。
- **版本。** 分开问两件。`version` 是这个 Mod 自己的版本。`minManagerVersion` 默认 `1.3.14`，只有确实依赖更新的管理器行为时才提高。
- **分类。** 让作者从下面选一个，不要凭名字里的「伤害」或「经济」替他选。
  - `OverlayUI`：叠在画面上的信息。
  - `QoL`：少点几下、更好操作，不改演算。
  - `Camera`：只动镜头。
  - `CombatAssist`：战斗过程中的辅助。选这个仍要按下一节看挂钩，分类本身不是风险等级。
  - `Economy`：补给、售价、收支的显示或操作。
  - `ReplayDebug`：回放或调试。
  - `Misc`：以上都不是。
- **标签。** 几个短词，写入 `tags`。标签不能代替分类。
- **冲突。** 和哪个已有 `id` 同时装进游戏会坏。没有就明确写没有。有的话双方都要列入 `conflicts`，`reason` 用字符串。对方 `id` 必须已经在目录里。不要自己和自己冲突。这一条由维护者写入 `catalog.json`，你先把双方 `id` 和原因问清楚。
- **预览图。** 有或没有。有则路径是 `preview`，写了 `previewSha256` 就必须和文件一致。
- **安装位置。** 默认 `type` 为 `MelonMod`。只有作者明确要插件、UserLibs 或 UserData 时，才改成 `MelonPlugin`、`MelonUserLibs`、`MelonUserData`。不要自造第五种。

## 两套「必填」不要混

校验脚本 `scripts/validate_catalog.py` 会拒绝的是：空的 `id`、`name`、`file`，以及非法的 `sha256`、`size`、分类、冲突和分片。

`author`、`summary`、`category`、`version` 在脚本里可以缺。脚本通过，不等于简介合格。本标准仍要求你在上一节问齐，再交给作者看。

目录合同：

- `sha256` 和 `size` 用脚本写，不要手改。
- `parts` 和 `bundle` 不能同时有。每个分片小于 100MB，按顺序拼回去必须等于整文件的 `sha256` 和 `size`。
- 单文件超过 100MB、git 放不下时，才用 https 的 `originUrl`。哈希仍然必填。

改完二进制后运行 `python scripts/validate_catalog.py`。不过，就不要告诉作者可以上架。

## 管理器会怎么看你的 DLL

启用前，管理器用静态扫描看 Harmony 挂钩，不看文件名，也不看注释。它不会改你的 DLL。没有 DLL 的目录项等级是「未检测」，不拦下载。

等级以返回类型和挂钩目标为准，不看函数体里有没有真的跳过原函数。

- **低。** 挂钩目标不在下面两张表里。启用时只显示，不弹确认。界面、相机、点游戏自己的按钮，属于这里。
- **中。** 挂在观察点或部署时间上，但又不是下面的「高」。启用前要玩家确认。
- **高。** 两种情况，启用前都要确认。一是前缀的返回类型为 `bool`，且目标在观察点或部署时间里。扫描器只看这个返回类型，即使函数体从不返回 false，也仍是高。二是后缀挂在部署时间那三个方法上，不论返回类型。
- **未检测。** DLL 读不出来，或手工补丁对不上目标。不要把它说成低风险。

观察点：

- `FightActor.ReduceLife`
- `DamagePerformer.Perform`
- `Player.AddSupply`、`Player.AddRoundSupply`、`Player.ReduceSupply`、`Player.SetSupply`
- `BattleStatisticManager.OnFightEnd`
- `BattleSystem.OnFightOver`

部署时间：

- `ProcessController.IsStateTimesUp`
- `ProcessController.GetMaxStateTime`
- `ProcessController.GetDeployTime`

作者侧约定：

- 次级界面、相机、好友列表不要挂到观察点。
- 如果必须在观察点上只读：前缀里的异常自己吃掉，让原函数继续执行；前缀不要声明为返回 `bool`；不改伤害、补给、部署时间的返回值。
- 正式对局只提交游戏本来就有的操作（撤回、道具、加速投票）。回放里才允许改部署计时，并且用「当前是不是回放」当门闩。门闩不成立时执行原函数。
- 游戏版本对不上、方法已经不存在时，整段挂钩不装。

不要用名字里的「伤害」「经济」给 Mod 定级。不要把挂钩目标藏进字符串去骗扫描。扫描看的是 Harmony 特性。

## 不要做的事

- 不要改管理器源码来迁就一个 Mod。
- 不要在游戏进行中改写已安装的 DLL。
- 不要把一次 Data Error 写成永久封号。
- 不要照抄简介里的「1.3.13」。
- 不要为了让扫描显示「低」而把会改演算的逻辑藏进运行时拼出来的调用。
- 不要追问或写明交件渠道。
