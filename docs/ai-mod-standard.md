# 给 AI 的 Mod 开发标准

你正在帮一位钢铁指挥官 Mod 作者写 Mod。你只有这一份文档。不要假设自己能打开管理器源码、社区目录仓库或任何校验脚本。本文没有写出的类名和脚本名，就当不存在。

不要问作者用哪条路把成品交出去。下面的规则与交件方式无关。

现在的管理器是 `2.0.0`。这只说明管理器自己的版本。普通 Mod 的 `minManagerVersion` 仍写 `1.3.14`，主包加副包仍不得低于 `1.3.15`。不要因为管理器变成了 `2.0.0`，就把门槛写成 `2.0.0`。

你要交出来的是：一份能在 MelonLoader 0.7.3 里加载的 Mod（类继承 `MelonMod`），可选的预览图，以及按本文形状起草的目录字段。你不改管理器，不在游戏运行时改写别人已经编译好的 DLL，也不承诺「装了这个就不会封号」。

Data Error 的公开后果是：这一局判负，并且不能重连。它不是已经核实的永久封禁。游戏自己的缺陷和丢包也会写出同一条记录。

## 两个词

目录条目是一条 Mod 在社区目录里的记录。玩家通过管理器下载时，管理器读的就是这些字段。

`sha256` 是文件原始字节的 SHA-256，64 个小写十六进制字符，不要 Base64，不要空格。`size` 是字节数，不是 KB 或 MB。手里有那份文件，就自己算。文件还没导出，就把这两个字段空着，不要编。不要问作者要这两个数。

100MB 等于 `100 * 1024 * 1024`，也就是 104857600 字节。管理器能下载的每一份文件都必须小于这个数。达到或超过，下载会被拒绝。

## 先看体积

写代码之前，先估计玩家要装下的全部字节：主 DLL，加上要一起装的文字、视频和其他文件。导出之后用真实长度再量一次。

只走一条：

- **一个 DLL，并且小于 100MB。** 作者只编译这一份 DLL。目录里仍写成下面的「一片」。不要加 `bundle`，不要再准备第二份整包。`minManagerVersion` 写 `1.3.14`。
- **仍然只是一个 DLL，但达到或超过 100MB。** 把这一个 DLL 按顺序切成 `0000`、`0001`…… 每片小于 100MB。按顺序拼回去必须等于原来的 DLL。这仍是一个文件，不要用 `bundle`。`minManagerVersion` 写 `1.3.14`。
- **要带文字、视频或其他素材，这些文件合在一起达到或超过 100MB，或者本来就要装多个文件。** 不要做成一个达到 100MB 的单文件，也不要用分片去装多个文件。按「主包和副包」写。`minManagerVersion` 不得低于 `1.3.15`。身份、简介和挂钩仍按后面各节。

小于 100MB 也写成片，是因为发布时不提供 `file` 那个地址上的整包，只提供片。1.3.12 和更早的管理器只会按 `file` 去下整包，下不到就失败。1.3.13 会把片按顺序拼回 DLL，所以它仍能下载，但它不读 `minManagerVersion`。1.3.14 和更高版本会拼片，也会读版本门槛。

## 一片 DLL 的目录长这样

`id` 用小写字母、数字、连字符，并且和文件夹名相同。`file` 写成 `mods/<id>/<程序集文件名>.dll`。片写在 `parts` 里，路径是 `mods/<id>/parts/0000` 起，四位数字，顺序就是拼接顺序。

小于 100MB 的 DLL 只有 `0000` 一片，这一片的字节、`sha256`、`size` 和整份 DLL 相同。条目顶上的 `sha256` 和 `size` 也是整份 DLL 的。`parts` 和 `bundle` 不能同时出现。

```json
{
  "id": "demo-grid",
  "name": "示例网格",
  "author": "作者名",
  "version": "1.0.0",
  "summary": "在画面上显示网格。按 F6 开关。正式服和测试服都可以用。",
  "file": "mods/demo-grid/DemoGrid.dll",
  "sha256": "有了 DLL 再填 64 位小写十六进制",
  "size": 8192,
  "preview": "mods/demo-grid/preview.png",
  "previewSha256": "有了图片再填",
  "type": "MelonMod",
  "category": "OverlayUI",
  "tags": ["grid"],
  "minManagerVersion": "1.3.14",
  "parts": [
    {
      "file": "mods/demo-grid/parts/0000",
      "sha256": "与上面的整份 DLL 相同",
      "size": 8192
    }
  ]
}
```

上面的 `sha256` 是说明，不是可以照抄的哈希。没有文件就删掉 `sha256` 和 `previewSha256`，不要留这句说明。

## 主包和副包

只在「先看体积」走到第三条时使用。一个 Mod 仍然只有一个 `id`。用 `bundle`，不要用 `parts`。

`bundle` 的每个成员有四项：

- `path`：装进游戏后，相对这个 Mod 自己的目录。不能是绝对路径，不能含 `..`。同一条里不能重复。
- `file`：这一份在目录文件树里的位置，放在 `mods/<id>/payload/` 下。
- `sha256` 和 `size`：这一份自己的。

其中一份是主包，文件名必须和条目 `file` 的文件名相同。条目顶上的 `sha256` 和 `size` 等于这一份主包，不是所有成员加起来。每个成员都要小于 100MB。

副包是常态素材：文字、视频，以及其他这次不改的文件。

```json
{
  "id": "demo-guide",
  "name": "示例指南",
  "author": "作者名",
  "version": "1.0.0",
  "summary": "悬停单位时显示说明并播放短片。按 F3 开关。正式服和测试服都可以用。",
  "file": "mods/demo-guide/DemoGuide.dll",
  "sha256": "只等于主包 DLL",
  "size": 873984,
  "type": "MelonMod",
  "category": "OverlayUI",
  "tags": ["guide"],
  "minManagerVersion": "1.3.15",
  "bundle": [
    {
      "path": "DemoGuide.dll",
      "file": "mods/demo-guide/payload/DemoGuide.dll",
      "sha256": "只等于主包 DLL",
      "size": 873984
    },
    {
      "path": "DemoGuide.Assets/DemoGuide.Videos.001.dll",
      "file": "mods/demo-guide/payload/DemoGuide.Assets/DemoGuide.Videos.001.dll",
      "sha256": "这一段视频自己的",
      "size": 44000000
    }
  ]
}
```

`873984` 只是在说明「主包可以远小于 100MB，大的是副包」。换成你自己的字节数。哈希同样不能照抄。

更新只动主包时：

- 换主包的字节，并重算主包的 `sha256`、`size`，以及条目顶上的 `sha256`、`size`。
- `version` 写成这个 Mod 自己的新版本。
- 没改过的副包：`path`、`file`、`sha256`、`size` 保持和上一版逐字相同。不要重新导出一遍再当成新文件。
- 不要把视频或文字再打进主包。
- 不要改 `id`。改了 `id`，管理器会把它当成另一个 Mod，玩家等于第一次安装，全部文件都要下载。

删掉一个副包，或只改 `path` 不改字节，管理器不一定会把它显示成可更新。它比较的是哈希集合，不比较路径。要让玩家看到更新，至少让一份仍留在列表里的文件哈希发生变化，通常就是主包。

包括 `2.0.0` 在内，玩家更新这种 Mod 时，管理器会把 `bundle` 里的每一份都重新下载，再整份换进本地库。副包哈希没变也下载。不要告诉作者或玩家「只更新主包、副包不会再下」。保持副包不变，是为了目录里的记录和文件对得上，不是因为管理器已经会跳过它们。

管理器已经能判断要不要更新：主包哈希变了，本地没有这份新哈希，条目就是可更新。它还不会在下载时跳过未变化的成员。第一次安装、本地副包对不上目录哈希、或作者真的改了某个副包，那一份本来就要下载。

## 谁能下载

玩家手里的管理器能不能下载这个 Mod，只看目录字段 `minManagerVersion`。不看 Mod 里的代码，也不看简介里的句子。不要在简介或译文里写管理器版本。

这个门槛只在一种时候生效：玩家通过管理器下载或更新。玩家从别处拿到文件，再导入管理器（DLL、压缩包或文件夹），或者直接放进游戏，都不受这个门槛限制。导入之后可以照常启用。启用时的挂钩确认见「管理器怎么给 DLL 定级」，跟文件从哪来无关。

`1.3.14` 和更高版本会在下载、更新前比较这个字段和自己的版本：

- 当前版本低于字段：拒绝下载，并提示先更新管理器。
- 当前版本等于或高于字段：允许下载。
- 字段空着：不设下限。
- 字段写错就拒绝。合法写法是恰好三段整数，每段 0 到 65535，例如 `1.3.14`。不要写 `v1.3.14`、`1.3.14.1`、`1.03.14`。比较时 `1.3.9` 低于 `1.3.14`。
- 已经在本地、目录哈希没变：不会为了这个字段再下一遍。导入、放进游戏、启用、停用，都不做这次比较。

`1.3.13` 和更早的管理器不读这个字段。写成 `2.0.0` 也拦不住它们。1.3.13 仍会下载带 `parts` 的包。1.3.12 和更早则因为没有整包而失败，见「先看体积」。

怎么填：

- 普通单 DLL：写 `1.3.14`。
- 主包加副包：不得低于 `1.3.15`。素材包按文件夹安装从这一版开始。不要为了写成「最新」就填 `1.3.17`。
- 这个 Mod 确实依赖 `1.3.14` 之后才有的管理器行为：写成第一个具备该行为的版本。例如要让 1.3.14、1.3.15、1.3.16 都拒绝，而 1.3.17 和 `2.0.0` 可以下，就写 `1.3.17`。`2.0.0` 高于 `1.3.17`，所以它也能下。这仍然拦不住不读该字段的 1.3.13 和更早版本。
- 说不清依赖的是哪一版行为：停下来问作者。不要猜成 `2.0.0`。

## 先问完再写

缺了下面任何一项，就停下来问作者。不得用占位符，也不得从文件名猜作者名、版本或支持哪一端。体积走哪一条，按「先看体积」自己量。

- **身份。** 玩家看见的作者名，写入 `author`。联系方式不写进简介。
- **标识。** 提议一个 `id`。你看不到现在的目录，所以必须请作者确认这个 `id` 还没有被占用。
- **名称。** 中文显示名，写入 `name`。
- **简介。** `summary` 只写三件事：玩家能做什么、用哪个键、正式服 / 测试服 / 两者。目录没有单独的游戏端字段。不超过 400 字。不要写管理器版本。
- **译文。** 再起草英文 `en`、德文 `de`、日文 `ja`、俄文 `ru` 的名称和简介，给作者看过再定稿。形状是 `"locales": { "en": { "name": "...", "summary": "..." } }`，四种语言都写。译文里也不要写管理器版本。
- **版本。** `version` 是这个 Mod 自己的版本，例如 `1.0.0`。`minManagerVersion` 按「谁能下载」填。两件分开问。
- **分类。** 让作者从下面选一个，不要凭名字里的「伤害」或「经济」替他选。选 `CombatAssist` 时仍要按「管理器怎么给 DLL 定级」看挂钩。
  - `OverlayUI`：叠在画面上的信息。
  - `QoL`：少点几下、更好操作，不改演算。
  - `Camera`：只动镜头。
  - `CombatAssist`：战斗过程中的辅助。
  - `Economy`：补给、售价、收支的显示或操作。
  - `ReplayDebug`：回放或调试。
  - `Misc`：以上都不是。
- **标签。** 几个短词，写入 `tags`，字符串数组。标签不能代替分类。
- **冲突。** 和哪个已有 `id` 同时装进游戏会坏。没有就明确写没有。有的话记成 `conflicts` 数组，每一项是 `{ "id": "对方的id", "reason": "原因" }`。不能指向自己。对方 `id` 必须已经在目录里；你看不到目录，就请作者给出对方的 `id`。双方都要写。收录时才会写进目录，你先把双方 `id` 和原因交给作者。
- **预览图。** 有或没有。有则路径是 `mods/<id>/preview.png`，字段名 `preview`。`previewSha256` 是这张图的 SHA-256。
- **安装位置。** 默认 `type` 为 `MelonMod`。只有作者明确要插件、UserLibs 或 UserData 时，才改成 `MelonPlugin`、`MelonUserLibs`、`MelonUserData`。不要自造第五种。

收录时会直接退回的是：空的 `id`、`name`、`file`，以及不合法的 `sha256`、`size`、分类、冲突、分片、素材包和 `minManagerVersion`。`minManagerVersion` 可以整段不写；写了就必须是三段整数。

`author`、`summary`、`category`、`version` 即使没收录检查，你也必须在上面问齐，再交给作者看。问齐了，也不要告诉作者因此可以上架。

不要写 `originUrl`。那是一个指向别处的下载地址。文件达到 100MB 时不要改用外链，按「先看体积」切片或拆成主包和副包。

## 管理器怎么给 DLL 定级

启用前，管理器看 DLL 上的 Harmony 特性，不看文件名，也不看注释。它不会改你的 DLL。没有 DLL 的目录项等级是「未检测」，不拦下载。

前缀指 Harmony 的 Prefix，后缀指 Postfix。等级看返回类型和挂钩目标，不看函数体里有没有真的跳过原函数。返回类型写成 `bool` 的前缀，即使函数体从不返回 false，也按「高」算。

- **低。** 挂钩目标不在下面两张表里。启用时只显示，不弹确认。界面、相机、点游戏自己的按钮，属于这里。
- **中。** 挂在观察点或部署时间上，但又不是下面的「高」。启用前要玩家确认。
- **高。** 两种情况，启用前都要确认。一是前缀的返回类型为 `bool`，且目标在观察点或部署时间里。二是后缀挂在部署时间那三个方法上，不论返回类型。
- **未检测。** DLL 读不出来，或手工补丁对不上目标。不要把它说成低风险。

观察点：

- `FightActor.ReduceLife`
- `DamagePerformer.Perform`
- `Player.AddSupply`、`Player.AddRoundSupply`、`Player.ReduceSupply`、`Player.SetSupply`
- `BattleStatisticManager.OnFightEnd`
- `BattleSystem.OnFightOver`

部署时间：

- `ProcessController.IsStateTimesUp`
- `ProcessController.GetMaxStateTime`
- `ProcessController.GetDeployTime`

作者侧约定：

- 次级界面、相机、好友列表不要挂到观察点。
- 如果必须在观察点上只读：前缀里的异常自己吃掉，让原函数继续执行；前缀不要声明为返回 `bool`；不改伤害、补给、部署时间的返回值。
- 正式对局只提交游戏本来就有的操作（撤回、道具、加速投票）。回放里才允许改部署计时，并且用「当前是不是回放」当门闩。门闩不成立时执行原函数。
- 游戏版本对不上、方法已经不存在时，整段挂钩不装。

不要用名字里的「伤害」「经济」给 Mod 定级。不要把挂钩目标藏进运行时拼出来的字符串。管理器看的是写在方法上的 Harmony 特性。

## 不要做的事

- 不要改管理器来迁就一个 Mod。
- 不要在游戏进行中改写已安装的 DLL。
- 不要把一次 Data Error 写成永久封号。
- 不要在简介或译文里写管理器版本，也不要写「需要 1.3.13」。
- 不要为了让扫描显示「低」而把会改演算的逻辑藏进运行时拼出来的调用。
- 不要追问或写明交件渠道。
- 不要在体积还没量之前就决定用分片还是主包副包。
- 不要把 `bundle` 写成 `parts`，也不要让任何一个成员达到或超过 100MB。
- 不要让主包加副包时，条目顶上的 `sha256` 等于所有文件拼起来的哈希。它必须等于主包。
- 不要承诺 `2.0.0` 的玩家更新时只会下载主包。
